# PRD: イベントモード — 居酒屋・イベント向け

## ユースケース

居酒屋でPCにデプロイされたURLを開き、イベント中にリアルタイムでメッセージを表示する。

**シナリオ**
- 店内のPCで表示用ページを開く
- その場にいる客も、オンラインの視聴者も入力用ページからメッセージを送信
- メッセージが来るとLED Boardに表示
- UXとして履歴を保存

---

## 機能要件

### 1. 表示用ページ（既存index.htmlの拡張）

**現在の機能**
- LED表示
- SSE受信
- カラー/サイズ/速度調整

**追加機能**
- イベントモード切替
- メッセージ履歴表示
- 絵文字スタンプ対応

### 2. 入力用ページ（新規：input.html）

**機能**
- シンプルなテキスト入力
- 絵文字ピッカー
- 送信ボタン
- QRコード表示（スマホからアクセス用）
- 送信履歴

**入力方法**
- テキストボックス
- プリセットメッセージ
- 絵文字スタンプ

### 3. 認証・制限（V2）

**V1**
- 無制限入力
- IPベースの簡易レート制限

**V2（課金版）**
- ユーザー認証
- 回数制限（無料: 10回/日、有料: 無制限）
- カスタム絵文字
- プレミアムカラー

### 4. 履歴保存

**機能**
- 全メッセージをSupabaseに保存
- イベントごとの履歴ページ
- CSVエクスポート
- 画像保存（スクリーンショット）

### 5. 寄せ書きモード（非リアルタイム）

**機能**
- 事前にメッセージを投稿できる寄せ書きボード
- 投稿されたメッセージが時間経過で順次表示
- リアルタイム性は必須ではない
- 表示間隔を調整可能

**ユースケース**
- イベント開始前に参加者がメッセージを投稿
- イベント中に寄せ書きが自動で流れる
- オフライン環境でも動作

**API**
- POST /api/messages/batch（一括投稿）
- GET /api/messages/queue（待ち行列取得）
- POST /api/messages/next（次のメッセージ取得）

## 技術仕様

### 入力用ページ

```
input.html
├── テキスト入力
├── 絵文字ピッカー
├── 送信ボタン
├── QRコード（表示用ページURL）
└── 送信履歴
```

### API

**POST /api/message**（既存）
```json
{
  "text": "メッセージ",
  "source": "event-input",
  "eventId": "event-123"
}
```

**GET /api/events/:id/history**
```json
{
  "messages": [
    { "text": "メッセージ", "timestamp": "2024-01-01T00:00:00Z", "source": "online" }
  ]
}
```

### 認証（V2）

- JWTトークン
- Supabase Auth
- Stripe決済連携

## UIデザイン

### 表示用ページ

- モード切替: 通常 / イベント
- イベントモード時:
  - イベント名表示
  - 参加者数表示
  - 履歴ボタン

### 入力用ページ

- モバイルファースト
- 大きな入力ボックス
- ワンタップ送信
- QRコード自動生成
