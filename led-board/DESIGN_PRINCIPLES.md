# 設計原則

## コア原則

1. **統一API**: POST /api/message 1つで全サービス連携
2. **依存ゼロ**: サービス間の直接依存を排除
3. **プッシュ型**: ポーリングなしで即時反映（SSE優先）
4. **シンプル優先**: 過度な抽象化を避ける
5. **段階的進化**: 必要になったらプラグイン化

## アーキテクチャ

- モノリス → 機能肥大したら分割
- ローカルSSE → クラウドSupabase（フォールバック）
- Server Mode（フル機能）+ Static Mode（軽量）

## 実装

- 型安全: TypeScript strict mode
- エラーハンドリング: 統一フォーマット
- 設定: 環境変数 + config.ts集約
- ログ: CSV + 標準出力

## UI

- 単一実装: index.html（vanilla JS）
- レスポンシブ: モバイル対応
- アクセシビリティ: キーボード操作

## テスト

- 単体テスト: コア機能
- 統合テスト: APIエンドポイント
- E2E: SSE + Supabase連携
